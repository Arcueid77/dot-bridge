# 本机管理界面

在浏览器里查看八个渠道的接入进度、处理订阅问题、选择下次启动的渠道，并准备整套升级。

先按[安装说明](operations.md)准备已有配置，再运行：

```bash
node bin/dotbridge.js ui --config /var/lib/dot-bridge/bridge.json
```

用最终运行用户启动。命令会显示一个本机地址，默认是 `http://127.0.0.1:5399`。打开它即可，关闭页面不会停止桥服务；在终端按 Ctrl+C 则关闭管理界面。

Windows 使用自己的清单路径，例如：

```powershell
node bin/dotbridge.js ui --config 'C:\DotBridgePrivate\bridge.json'
```

先看一版不连接账号的演示：

```bash
node bin/dotbridge.js ui --demo
```

演示会明确标注，不读取真实账号或保存配置。端口已占用时，改用 `--port 5400`，或用 `--port 0` 自动选择一个空闲端口。

## 看懂连接进度

- **未启用**：清单尚未选择此渠道，页面不会自动开启它。
- **配置待完善**：先核对私有配置和最终运行用户。
- **服务未连接**：本机的对应桥服务尚未可访问。
- **待本人配对**：在私密终端完成本人确认，保留生成的受保护绑定文件。
- **平台未连接**：核对平台登录与出网；迁移时确认旧消费者已经停止。
- **待 dot 订阅**：平台已连接，还需要原 dot 的有效事件订阅才能自动回复。
- **订阅即将到期／已到期**：由原 dot 续订，界面只显示实际返回的有效期。
- **链路就绪**：绑定、平台连接和订阅均已就绪；从本人私聊发消息确认实际回复。

较早组件没有提供的状态会显示为待核对。页面不会根据配置存在、工具可发现或默认有效期推测服务已经接通。

## 接入与配对

选择一个渠道，按“平台应用 → 本人配对 → 原 dot 订阅 → 私聊确认”逐项处理。已有本人绑定时，界面会提示保留它；不需要再扫码或生成另一份绑定。

配对口令、二维码、Token、Secret 和身份值仍在私密终端及受保护文件中处理，管理页面不接收这些内容。首次配对前确认同一账号的旧消费者已经停止，并确认私有凭据的保存位置。

原 dot 的订阅由它自己的真实订阅流程创建。页面提供可复制的准确指令，以及已有请求的脱敏失败阶段。没有记录时，无法还原之前失败；不要靠反复创建订阅排查问题。回调域名需要新增批准时，先核对实际域名，再按原安全流程处理。

LINE 回复图片或语音时，需要先提供一个临时下载地址，由 LINE 取走内容。可以使用现有域名，不必另买服务器；准备好下载入口后才启用媒体回复，页面不会自动开放托管。

## 保存运行设置

勾选下次需要启用的渠道，先点“检查所选配置”。对应环境文件需要已经存在，并通过组件的离线检查。

点“保存下次启动配置”后，会再次确认、重新检查并保留原清单的私有备份。它只修改启用列表，保留运行模式、数据目录和原私有文件引用。正在运行的服务不会重启，凭据、白名单和订阅也不会改变。

由管理员核对新选择后，沿用现有服务流程重启。新增或取消渠道会影响 systemd 单元组成，需要重新生成并核对服务文件。

如果清单在页面打开后已被其他操作修改，保存会拒绝覆盖，先刷新再继续。目录或文件没有通过私有权限和链接检查时，请以最终运行用户处理，不要放宽权限绕过检查。

## 准备升级

先把已审核的发行版放在本机目录中。启动界面时指定其父目录，例如：

```bash
node bin/dotbridge.js ui --config /var/lib/dot-bridge/bridge.json --releases-dir /opt/dot-bridge/releases
```

“版本与升级”会列出这些发行目录。选择目标后，可以检查包哈希、锁文件、组件版本变化、所选渠道、当前 Node 和私有配置，并下载具体升级操作单。

完整回复队列计数如果不可用，会明确列为待核对，不能拿页面最多显示的几条引用代替。存在等待、处理中或结果不明的任务时，先处理或安排停机，不删队列、不改状态、不自动重发。

包与清单一致仅说明安装包完整；发行版来源审核、数据库一致性备份、目标版本的配置检查以及 systemd 切换，仍由管理员在最终主机完成。页面不会下载或执行目标代码，也不会把预检显示为已经升级。

## 在 VPS 上使用

管理界面只监听本机地址，不开放公网管理端口。可以用已有 SSH 连接做端口转发。两端使用相同端口，例如：

```bash
ssh -N -L 5399:127.0.0.1:5399 <已有的服务器登录目标>
```

然后在部署电脑打开 `http://127.0.0.1:5399`。不要把监听地址改为 `0.0.0.0`，也不需要为管理界面调整防火墙或 Tunnel 权限。
