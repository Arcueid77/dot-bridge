# 在聊天里使用 DotBridge

[English](channel-experience.en.md) · [返回首页](../README.md)

## 按钮和选择菜单

可以告诉原 dot“给我 PDF、Markdown 两个按钮，我选完再继续”。飞书、Telegram 和 Discord 可以显示原生按钮或单选菜单。选项有效期最长十分钟，只有发起这次请求的人能在原会话、原话题中选择。重复点击同一项会沿用第一次结果。

点选后，桥会把选择作为一条新输入交给原 dot。还可以让 dot 为当前提醒提供“暂停”“恢复”“取消”按钮，按钮只操作它绑定的提醒编号和版本。其他渠道显示编号选项，直接回复编号即可继续。

Telegram 的本人私聊还会显示 `/help`、`/status`、`/queue`、`/subscription` 和 `/cancel` 命令菜单。飞书应用需在“事件与回调”的回调配置中订阅 `card.action.trigger`，选择使用长连接接收回调。具体操作见[飞书官方说明](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)。已有应用的回调配置由应用管理员核对后调整。

## 阅读较长的回答

可以说“这次请发 Markdown 文件”，让 dot 在最终回复中选择文件交付。Telegram、Discord 和 LINE 也支持明确选择分段文字。自动模式继续使用该渠道的偏好。

分段会尽量保留段落、代码块和表格，长表格会重复表头。渐进回复会合并过密的小更新，完成时再提交最终内容。QQ 需要在开始流式回复前选定文件交付。

## 图片、相册和生成的文件

Telegram 同一相册中的图片会合成一条输入，并保留说明文字。可以继续说“把收到的图片原样发回”，桥按原消息的附件编号回发。

原 dot 生成的报告或图片也可以通过附件上传工具交给桥，再发回原会话。dot 的工具环境需要能够以程序读取生成文件并调用上传工具。上传按分块校验大小和 SHA-256，完成后仍需提交最终发送。原文件上限 5 MiB，各渠道仍有自己的格式限制。

## 管理提醒

可以在对话中说“工作日上午九点提醒我喝水，到月底结束”，或“每三十分钟提醒一次，今天下午六点结束”。支持一次、每天、每周、周一至周五和固定间隔，间隔最短五分钟。

这里的工作日按周一至周五计算。

管理页的“我的提醒”可以新建、编辑、暂停、恢复、取消和查看最近二十次发送记录。创建时可先保存为暂停，再核对内容和时间。发送目标始终是所选渠道已经绑定的本人私聊，该渠道需已启用主动发送。

恢复重复提醒会跳过暂停期间的旧时间点。已经错过的一次性提醒，需要先改到未来时间再恢复。发送结果不明时会保留记录供本人核对。完整规则见[定时消息](scheduled-messages.md)，管理页的访问方式见[管理界面](management.md)。
