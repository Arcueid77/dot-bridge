# 让 dot 定时发消息

可以在原 dot 中安排提醒，也可以在已接入的本人私聊里告诉它，把消息发到另一个已绑定的渠道。例如：

> 明天上午九点，用飞书提醒我交周报。按北京时间，只提醒一次。

> 每周五下午五点，在 Telegram 提醒我备份项目，到年底结束。

dot 会先核对目标渠道是否已允许主动发送，再保存提醒。它应回报发送时间、时区、目标渠道和提醒编号。只有返回了保存成功的编号，才算安排完成。可以继续说“把刚才的提醒改到十点”或“取消每周五的备份提醒”。

发送目标只允许各渠道已经绑定的本人私聊，不能指定其他人或群组。发起请求的渠道和接收提醒的渠道可以不同；原有的消息回复和事件订阅继续沿用。

## 哪些渠道可以接收

| 接收渠道 | 主动文字和定时提醒 |
| --- | --- |
| 飞书 | 支持，使用已配对应用向本人私聊发送 |
| Telegram | 支持，使用已配对的 Bot 私聊 |
| Discord | 支持，只使用已核对的一对一私聊 |
| 钉钉 | 支持，通过应用机器人接口向已配对的本人发送；应用需有相应发送权限和额度 |
| 企业微信 | 支持，使用智能机器人长连接的主动消息接口 |
| LINE | 支持，使用官方账号的 push 接口；本人需满足平台接收条件，且可能计入账号消息额度 |
| QQ | 本版本暂不开放独立主动推送，当前账号的平台资格与额度尚未确认。仍可在 QQ 中请求 dot 安排向其他可用渠道发送 |
| 微信 iLink | 本版本暂不开放独立主动推送；现有发送依赖会话上下文。仍可在微信中请求 dot 安排向其他可用渠道发送 |

“组件支持”与“这个账号已经启用”是两件事。未配置账号的渠道继续停用。调用 `check_<渠道>_outbound` 查看当前是否允许发送；不会因为查状态而发送消息或扩大权限。

## 固定提醒与每日生成内容

固定文字提醒由 DotBridge 保存在运行服务的服务器上，到点发送。你的本地电脑和原 dot 的对话窗口不必一直开着；服务器及目标平台账号需要正常运行。支持一次、每天、每周，每个提醒最多 2,000 字符。重复提醒必须写明结束日期，最长一年。

“每天帮我整理新闻再发到飞书”需要到点生成新内容。这种任务由原 dot 自己保存真实的定时任务，到点整理后调用 `send_lark_message`。dot 应确认它的定时任务确实保存成功；DotBridge 保存一段固定文字，不能代替这一步。现有收消息的事件任务无需重建。

每天、每周的固定提醒按指定时区的当地时间执行。夏令时跳过了该时刻，当天不发；同一时刻出现两次，只发一次。服务短暂停机时允许五分钟内的迟到提醒，超过五分钟的旧提醒跳过，避免恢复后集中补发。

## 启用与管理

主动发送默认关闭。管理员确认发送范围后，只在需要的渠道私有环境文件中增加：

```dotenv
DOT_BRIDGE_OUTBOUND=owner-text
```

重启对应渠道和加载了新版目录的聚合器，再在原插件刷新工具目录。不要把这个设置加到 QQ 或微信 iLink 的配置，也不要为此开放公网 MCP 端口、修改回调白名单或生成新 Token。关闭时设回 `disabled` 并重启；提醒记录仍保留，未来的发送停止。原有被动回复不受这个开关影响。

每个可用渠道提供这些工具，`<渠道>` 为 `lark`、`telegram` 等渠道标识：

| 工具 | 用途 |
| --- | --- |
| `check_<渠道>_outbound` | 查看支持情况与开关 |
| `send_<渠道>_message` | 立即发送一条新的本人私聊文字 |
| `schedule_<渠道>_message` | 保存固定文字提醒 |
| `list_<渠道>_scheduled_messages` | 列出近期待发或需要处理的提醒，最多 20 条 |
| `get_<渠道>_outbound` | 按保存的编号查看时间、状态与当前版本 |
| `update_<渠道>_scheduled_message` | 修改尚未到期的提醒，需带当前版本 |
| `cancel_<渠道>_scheduled_message` | 取消未开始发送的消息或后续提醒 |

提醒保存示例，使用目标渠道对应的工具名；时间须包含 UTC 偏移量，时区须为 IANA 名称：

```json
{
  "conversation": "owner",
  "text": "记得交周报",
  "send_at": "2026-11-03T09:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "repeat": "once",
  "until": null,
  "idempotency_key": "weekly-report-reminder-2026-11-03"
}
```

重复提醒把 `repeat` 改成 `daily` 或 `weekly`，并用 `until` 填写带偏移量的结束时间。同一个安排重试时必须沿用同一 `idempotency_key`；重复任务每次实际发送使用不同、可复现的时段编号。不能遇到超时就换一个编号重发。

状态为 `pending` 或 `active` 代表待发送，`sent` 代表平台已确认接收请求，并不代表你已读。`uncertain` 表示结果不明，后续重复发送会暂停；先核对聊天中的实际结果，不自动补发。已经开始发送的消息不能撤回，取消也不能抹掉不确定状态。

提醒正文在原有私有数据库中加密保存，沿用原存储密钥。尚未结束的提醒保留至结束；结束后的正文七天后逻辑清除，最小去重记录保留。SQLite 旧页、WAL、备份和系统日志不因此物理擦除。每渠道最多保存 100 个待处理安排，累计 10,000 个安排；容量满时明确拒绝新建，不自行删除旧去重记录。
